## Fix strongly recommended

### F1 The browser job reinstalls Chromium and its system packages on every run

- **Rework if left:** high
- **Effort:** S
- **Evidence:** `.github/workflows/ci.yml:63` "key: playwright-${{ runner.os }}-${{ steps.pw.outputs.version }}"
- **Case:** The cache missed on all four runs checked, so `playwright install --with-deps` ran each time: 18 s, 30 s, 1 min 59 s and 4 min 56 s. Run 281 took 8 min against the 5 min CI budget, with the job's timeout at 10 min, so one slow mirror day fails a PR that has nothing wrong with it. CI never runs on `main`, so no cache any PR can read is ever saved.
- **Fix:** Run the browser job inside the official Playwright image pinned to the same version as `@playwright/test` (1.64.0), which already holds Chromium and its packages, and drop the cache and both install steps. Measure one CI run before and after.

### F2 Ten of the thirteen browser specs break the one-smoke rule and each boots its own world

- **Rework if left:** high
- **Effort:** M
- **Evidence:** `tests/browser/lamp.spec.ts:3` "apart from the smoke so the smoke keeps its time"
- **Case:** RULES VR-23 allows a new browser test only for a bug that reached Morgan. Only touch and hunger trace to one in LESSONS (searched each spec's subject in docs/LESSONS.md). Clothes, lamp, mill, watch, strangers, flock, health, sickness, find and wild each settle a fresh world to read one sheet; eight of them took 41.9 s together locally. Each new bundle adds another, so the browser step grows with every phase.
- **Fix:** Move the text and content checks of those sheets into worker tests that read the snapshot in Node. Keep one `phone-sheets.spec.ts` that settles one world once (`describe.serial` with a shared page) and checks only what needs a browser: tap sizes and no sideways scroll. Share `settle`, `tick`, `skipOnce` and `phoneRules` from one helpers file (see F12). Then reword VR-23 to match.

## Other findings

### F3 The smoke has grown into a 46 s tour of every sheet

- **Rework if left:** medium
- **Effort:** M
- **Evidence:** `tests/browser/smoke.spec.ts:59` "The whole round makes the world three times (boot, reload, load)"
- **Case:** The comment is stale: the test loads the game five times (two `goto`, a reload, a Load and a second reload) and carries a 150 s timeout because stairs, Work folds, steppers, Build, Laws, alerts and send-back were added to it. It ran 46.5 s locally, the longest browser test. It also repeats the speed rule that `src/worker/pace.test.ts` already proves, with fixed waits.
- **Fix:** Cut the smoke back to VR-23's job (boots, runs, saves, reloads, continues) and move the sheet tour into the shared file in F2. Keep one check that Space pauses and that speed 3 moves the clock; drop the 50 to 130 ticks-a-second window.

### F4 Many unit files each step the same early colony from day 0

- **Rework if left:** medium
- **Effort:** M
- **Evidence:** `src/engine/people/tools.test.ts:145` "step(w, sim, 4 * DAY);"
- **Case:** With Bundle 0. The reader counted about 150 colony-days on seed `ledger` with default content, stepped from tick 0 file by file (tools 8 worlds, chandle, well, cellar, fire, stores, build, houses, roads), plus 7 `smoke` worlds in health and 6 worlds in sick. The sum of file times is 290 s; the wall time is about a third of that, so repeated early days cost every run.
- **Fix:** A test helper that caches one run per seed and content and hands out a clone at day 1, 3, 6, 9 or 12, used first by the tests that change nothing before stepping. Vitest already shares the module graph (`isolate: false`), so the cache lasts the whole run.

### F5 The quick check is over its 40 s budget and its slow list is out of date

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `vitest.config.ts:5` "files out so it stays under 30 s"
- **Case:** With Bundle 0. `npm run check` took 45.3 s and printed its own OVER warning: unit 33.4 s and format 7.7 s, because Prettier's cache was cold. Files that step 10 or more days (sick, smithy, loom, well, lines) are not on the slow list, while the comment still says 30 s.
- **Fix:** Rebuild the slow list from the JSON reporter's file times (every file over about 3 s) and fix the comment. Check only changed files for format in the quick tier, as the Story Generator does, and keep the whole-repo format check in check:full.
