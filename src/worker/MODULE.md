# worker

The Web Worker that owns the engine, runs the tick loop and answers the main thread.

- **Public API:** `index.ts`: `spawnSimWorker()`, `TICKS_PER_SECOND`, `SAVE_VERSION`, and the types `ToWorker`, `FromWorker`, `Speed`, `ClockView`, `ChunkView`, `LedgerLine`, `TileView` (`protocol.ts`; DECISIONS V-002; ARCHITECTURE "Worker protocol") and `SaveFile` (`save.ts`). `worker.ts` is the worker's entry; `pace.ts` the tick clock; `save.ts` builds and checks saves.
- **Messages in:** `init {seed, contentHash}` (a content mismatch stops the worker with an error naming both hashes; init and the future `load` both end in `adopt`: paused, everything resent), `setSpeed {speed}` (0 paused, 1 to 3), `command {tick, kind, data}`, `requestSnapshot`, `load {save}` (checked for format version, content hash and shape before anything is replaced; a refused save posts `loadRefused` and the running world carries on; an accepted one ends in `adopt`, like `init`), `save {auto}`, `export {kind: 'ndjson'}`, `inspect {x, y}`, `why {id}`. Save, export, inspect and why only read the world between ticks: they never step it, write a ledger line or draw from an RNG stream.
- **Messages out:** `ready {from: 'seed' | 'save', seed, contentHash, width, height}`; on each request, `events {batch}` (new ledger lines as `LedgerLine`s with their text and clock, if any) then `snapshot {tick, speed, clock, chunks}`; `saved {auto, save, clock}`; `loadRefused {reason}`; `exported {kind, name, text}`; `inspected {tile}` (`TileView` with its last-changed line, or undefined off the map); `causes {id, lines}` (`whyOf`, nearest first, with depth); `error {message}`.
- **Tick scheduler:** wakes every 10 ms but trusts `performance.now()`, not the timer: each wake runs the whole ticks owed for the real time elapsed at the current speed (10, 30, 100 a second), carrying the fraction. At most 250 ms is caught up after a stall; the rest is dropped. Pausing drops the fraction, so the tick stops dead.
- **Snapshots:** pulled, never pushed: the page asks once per frame with at most one request in flight. Chunks go out when their `world.map.chunkVersions` entry differs from the last one sent (all of them the first time), as transferred `Uint8Array`s.
- **Rules:** the only place the engine is instantiated. Speed and pause are worker settings, never game commands. Any throw stops the loop and posts `error`; the page shows it and offers a reload.
- **Tests:** `pace.test.ts` (speeds, pause, catch-up cap); `save.test.ts` (a save survives a structured clone whole; other content, another format or a damaged save is refused); the browser smoke (pause stops the tick, 3x runs, save and load).
