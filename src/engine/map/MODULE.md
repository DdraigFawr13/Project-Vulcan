# map

The valley's ground: every surface tile and what it is made of.

- **Public API:** `index.ts`: `mapSystem` (lays the map out in `init` when a world begins from a seed, never on load), `setTile(ctx, x, y, kind, cause)` (the only writer of a tile afterwards: it records `cause`, the event the caller emitted to explain the change, and raises the chunk's version), `CHUNK` (16), `chunksAcross(map)`, `chunksDown(map)`, `chunkTiles(map, cx, cy)` (one chunk's tiles as a `Uint8Array`, for the worker's snapshots).
- **Events:** emits `map.formed` (cites `world.begun`) once, at world creation; reads none.
- **State owned:** `world.map`: `width`, `height`, `tiles` (index into `content.terrain.kinds`, row by row), `tileCauses` (the id of the ledger line that last changed each tile, `map.formed` at first; the inspector's "last changed") and `chunkVersions` (one counter per chunk, raised when a tile in it changes, so the worker sends only changed chunks).
- **Invariants:** size and starting ground come from `content.terrain.surface`; every tile names an existing kind (`setTile` checks; content allows at most 256 kinds, as tiles travel as bytes). Tiles are kind indices, so a save is only valid with the content it was made with (P0.5 `load` refuses a different `contentHash`). The surface is generated in `init`; later generation (V-014's underground levels, made when first reached) will go through one generator entry point that `init` also calls and that emits a line citing its trigger. Flat ground until Phase 1, whose generator draws from a `worldgen` stream it declares then. One surface level for now: Phase 1 adds a level (`z`) to `MapState`, `setTile`, `ChunkView` and `inspect` together, before anything is built underground. Which picture a tile shows is the renderer's choice, never state.
- **Tests:** `src/engine/engine.test.ts` (the determinism test also compares the map).
