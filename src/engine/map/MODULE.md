# map

The valley's ground: every surface tile and what it is made of.

- **Public API:** `index.ts`: `mapSystem` (generates the surface in `init` when a world begins from a seed, never on load, from the `worldgen` stream), `setTile(ctx, x, y, kind, cause)` (the only writer of a tile afterwards: it records `cause`, the event the caller emitted to explain the change, and raises the chunk's version), `CHUNK` (16), `chunksAcross(map)`, `chunksDown(map)`, `chunkTiles(map, cx, cy)` (one chunk's ground, features and snow as `Uint8Array`s, for the worker's snapshots).
- **Generator:** `terrain.ts` lays the ground (climate drawn by weight, a trough along one of 16 written-out axes roughened by value noise, spurs from ridged noise, rock from `rock.line` metres above the valley floor (held between the `rock.wall` shares, so rock share varies by seed), scree and crags by percentile, the valley walls of one rock drawn by weight, rock colder than `rock.snowline` marked in the `snow` layer (the tile keeps its rock), biome from the forked temperature-by-rainfall table, fertility); `mountains.ts` raises massifs of drawn radius, height and stretch, each of one rock, bent by a warp field, placed by the layout `generator.layout` names in `generator.layouts` (`valley`: 5 to 8 ranges on the rims, mostly along the axis; `highlands`, kept for later: massifs inside the valley too); `features.ts` places trees in groves and old-growth stands, fallen logs, bushes and herbs in glades,, herbs and boulders from `features.json` and picks the start tile (nearest the middle with the start floors within `start.radius`, a square, counting only ground joined to the start without crossing rock: `reachableAround`); `noise.ts` is value noise on an integer lattice from the stream, smoothstep only, no transcendental math or square roots (V-006). Every dial, and every kind, biome and item id the generator names, is in `terrain.json` `generator`; features that clump into groves say so with `clumps`. The surface takes its draws from `worldgen` only in `init`; P1.3's lazy levels need their own per-level streams, so reaching levels in a different order cannot change them. `npm run map:stats` and `map:render` run it over `seeds.ts`.
- **Events:** emits `map.formed` (cites `world.begun`) once, at world creation, with the climate and main biome; reads none. Layers are written whole under that one line, never per tile.
- **State owned:** `world.map`: `width`, `height`, `tiles` (index into `content.terrain.kinds`, row by row), `tileCauses` (the id of the ledger line that last changed each tile, `map.formed` at first; the inspector's "last changed") and `chunkVersions` (one counter per chunk, raised when a tile in it changes, so the worker sends only changed chunks); the generator's layers as typed arrays (`elevation` Int16 metres, `biomes`, `fertility` 0 to 100, `features` 0 or 1 + index, `snow` 0 or 1, all Uint8), `startX`, `startY`, `climate`, `temperature`, `rainfall`. Features have no writer yet; the first milestone that fells a tree adds one beside `setTile`, raising the chunk's version.
- **Invariants:** size and starting ground come from `content.terrain.surface`; every tile names an existing kind (`setTile` checks; content allows at most 256 kinds, as tiles travel as bytes). Tiles are kind indices, so a save is only valid with the content it was made with (P0.5 `load` refuses a different `contentHash`). The surface is generated in `init`; later generation (V-014's underground levels, made when first reached) will go through one generator entry point that `init` also calls and that emits a line citing its trigger. One surface level for now: Phase 1 adds a level (`z`) to `MapState`, `setTile`, `ChunkView` and `inspect` together, before anything is built underground. Which picture a tile shows is the renderer's choice, never state.
- **Tests:** `src/engine/engine.test.ts` (the determinism test also compares the map); `map.test.ts` (the P1.1 start done-when on every seed in `seeds.ts`).
