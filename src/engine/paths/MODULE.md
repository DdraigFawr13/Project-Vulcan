# paths

Ways across the valley and the levels below: where people can walk, what each step costs, and the way from one place to another.

- **Public API:** `index.ts`: `findPath(content, map, from, to)` (the nodes stepped onto, ending on `to`; empty when already there; undefined when no way exists now), `canReach(content, map, from, to)` (a lookup, no search), `stepCost(content, map, a, b)` (one step between neighbours, corners and levels; 0 when it cannot be taken now), `walkAt(content, map, z, i)` (the tile's walking multiplier, 0 when it cannot be stood on), `costAt(content, map, z, i)` (what standing there costs in tenths of a plain step: the multiplier x 10, or `walking.road` on a road, P5.10), `besideReachable(world, content, reach, i, z)` (whether a side of tile `i`, never a corner, can be stood on and reached by what a `reachFrom` function says), `pack` and `unpack` (a `Spot {x, y, z}` as a `Node` number, `z * width * height + y * width + x`).
- **Walking:** stone, solid ground, deep water and blocking features (trees, boulders) are never walked; a terrain kind's `walk` multiplies a step (shallow water 3, marsh, scree and snow 2); frozen lake water is crossed at `walking.ice`. Steps cost `walking.straight` (10) or `walking.diagonal` (14) tenths, and a corner is cut only when both tiles beside it are open. A built wall (`map.built`, P3.1) is never walked; a door or floor is. A road part (P5.10) costs `walking.road` tenths (7) of a plain step, so steps cost `costAt` x `straight` or `diagonal` / 10, rounded down. Stairs or a shaft above meeting stairs or a shaft below link two levels at `walking.stairs`, or `walking.shaft` for a shaft on both. Dials in `terrain.json` `walking`.
- **Search:** `regions.ts` cuts each 16 by 16 chunk of each reached level into regions (walkable ground joined side to side inside it), links neighbouring regions across chunk edges and through stairs and shafts, and names each set of joined regions a component, so an unreachable goal is answered with no search. `search.ts` runs A* over regions (from each region's first tile), then A* over tiles inside only the regions on that way. Ties break by node number, so one query always gives one answer. Regions keep each tile's `costAt` and count each chunk's tiles cheaper than plain ground (`cheap`); while any exist the tile search's estimate counts every step at road cost, so the way found is still the cheapest.
- **State owned:** none saved. Regions and search buffers are kept beside the map object and worked out again from it: a chunk is relabelled when its version changes and a tile there now walks differently (felling, digging, ice coming or going); a version raised for snow or prints relabels nothing. Region ids are fixed by place (level, chunk, order of first tile), so a loaded world finds the same ways as the running one.
- **Events:** none; walking is never a ledger line (V-036).
- **Invariants:** pure and deterministic (V-006): whole-number costs, no square roots; reads only the map as it is now.
- **Tests:** `paths.test.ts` (ways avoid water, rock and trees and cut no corners; stairs lead between levels; a walled-off goal is refused without a search; the same query gives the same way on a reloaded map). `npm run paths` times searches with five walkers on the full map against P2.3's done-when.
