# log

The ledger: writes every event with its causes, refuses ones content has no text for, renders and exports them, and seals old days.

- **Public API:** `index.ts`: `emit(world, templates, type, fields)` appends `{id, tick, type, actors, subjects, causes, data}` to `world.log` and returns the id; `templatesOf(events)`; `renderEvent(event, templates, nameOf?)`; `toNdjson(events)`; `findEvent(lines, id)` (binary search over lines or stubs); `recordOf(world, id)` (a recent line, or the stub of an older cited one); `whyOf(world, id, limit?)` (an event's causes and theirs, nearest first, each once with its depth; a cause whose day is sealed comes back once as `older` and ends that branch: the inspector's "why?"); `sealDays(world, cited, recentDays?)`; `RECENT_DAYS` (7); `allLines(world)` (sealed days plus recent lines, for headless runs); types `EventFields`, `Templates`, `Cause`.
- **Policy (DECISIONS V-036):** a line is a change a player would read or trace. Steps walked, needs falling each tick, work progress and a hauling trip's pick-up and drop-off are state only. Budget: at most 15 lines per colonist per game day on the busiest day (`npm run budget`); a job is one line when taken and one when done or given up, never per trip.
- **State owned:** `world.log`, `world.stubs`, `world.segments`, `world.sealed` and `world.nextEventId`.
- **Sealing:** at each midnight (`step` calls it) every whole day older than the recent window leaves `log`: its lines become one NDJSON segment in `sealed` (for the worker to archive) and a `{day, key, first, last}` entry in `segments`; the key is the seed, the id range and a digest of the text, so two histories never share a key. Older lines still cited (by `cited`, a recent line's causes, or `world.begun`) are kept as `{id, tick, type}` stubs; stubs no longer cited are dropped.
- **Invariants:** ids rise by one from 1, across stubs then recent lines; an event's tick is the world's tick; `emit` throws when the type has no template, a slot is left empty or a cause is not an earlier line. The window changes no outcome: systems read only the current tick's lines.
- **Tests:** `src/engine/engine.test.ts` (the template check, calendar lines, "why?" chains, the whole stream identical with a 7-day or 400-day window); `src/worker/save.test.ts` (stubs survive a save; a remembered line is kept).
